# Dataset Documentation

## Overview

K-SETU includes seeded **synthetic demo data** for development, testing, and prototype demonstrations. The data illustrates the platform's e-waste collection, pricing, recycler, transaction, safety, and field-research workflows.

**All seeded records and CSV datasets are synthetic/demo data. They do not represent verified real-world users, facilities, transactions, prices, or field findings.**

## Seeded Data Summary

The seed script generates the following sample records:

| Data category               | Approximate quantity |
| --------------------------- | -------------------: |
| Collectors                  |                   11 |
| Recyclers                   |                    8 |
| Material categories         |                   11 |
| Current prices              |                   33 |
| Weekly price-history points |                 ~430 |
| E-waste lots                |                   34 |
| Transactions                |                  ~24 |
| Safety content rows         |                   24 |
| Field-research notes        |                    2 |

The seeded data also includes related ledger entries and traceability events, as well as unit-economics assumptions.

Safety content is provided in English (`en`), Hindi (`hi`), and Marathi (`mr`).

Quantities are based on the project's seed configuration and may change as the prototype evolves.

## Data Generation

Demo records are generated by the project's database seed script:

```bash
npx tsx src/db/seed.ts
```

The seed script is designed to be idempotent. On a fresh database, it creates the demo accounts first, followed by the sample records used by the application.

See [Database Documentation](./DATABASE.md) for database setup and seeding instructions.

## CSV Dataset Files

CSV mirrors intended for future machine-learning experimentation are located in:

```text
ml/datasets/
```

These files are prototype resources for exploration and future model development. Their presence does not imply that the data has been independently collected, validated, or approved for production model training.

Before using any dataset for model training or evaluation, review its contents, provenance, labels, licensing, data quality, and suitability for the intended task.

## Intended Use

The synthetic datasets support:

* Demonstrating collector and recycler workflows.
* Populating sample lots, quotes, and transaction histories.
* Illustrating pricing and price-history screens.
* Testing ledger and traceability interfaces.
* Presenting multilingual safety-content examples.
* Exploring future ML classification, estimation, anomaly-detection, and recommendation workflows.
* Demonstrating preliminary unit-economics assumptions.

## Limitations

* Sample records are synthetic and must not be presented as actual field observations.
* Demo prices are illustrative and are not live market quotations.
* Sample recycler profiles do not establish that a facility is licensed, verified, or currently operational.
* Synthetic records are not a substitute for representative, consented, and quality-checked real-world data.
* Prototype ML experiments using these files should be clearly distinguished from validated model performance.
* Field-research notes and unit-economics assumptions are examples, not independently verified findings.

## Responsible Use

When presenting K-SETU externally, label seeded content as **demo**, **sample**, or **synthetic** wherever users could mistake it for real data.

Do not use synthetic records to make unsupported claims about actual waste volumes, market prices, recycling capacity, user behavior, or environmental impact.

Any future real-world dataset should have documented provenance, appropriate permissions, privacy safeguards, and a clear data-quality review process.
